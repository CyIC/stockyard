## 1. Summary

Stockyard v1.0 turns Warren Bot into a **stock research library with two front ends**: the existing
Discord bot (still called **Warren**) and a new **command-line interface** whose primary consumer is an
AI agent that needs the same numbers without spending LLM tokens to compute them. A third front end, an
**MCP server**, follows in v1.1 on the same core.

The core produces the BetterInvesting **Stock Selection Guide (SSG)** analysis as *typed, structured
results*. Front ends never compute; they call the core and hand its results to a renderer (Discord
markdown, terminal text, or JSON).

## 2. Goals and non-goals

**Goals (v1.0)**

1. A pure core library: fetch → align → analyse → typed results. No Discord, no printing, no hidden
   file writes, no dependence on the wall clock.
2. A CLI for humans (text) and agents (`--json`, versioned schema, stable exit codes).
3. The Discord bot ported onto the core with today's commands (`!stock_report`/`!sr`, `!help`).
4. **Issue #5 / ADR-0001:** every year-over-year comparison reads Aligned Annual Fundamentals keyed on the
   income-statement fiscal period-end.
5. **Issue #2:** a short-history company produces a partial report with explicit warnings, never a crash.

**Non-goals (v1.0)** — deliberately deferred

| Item | Target | Why |
|---|---|---|
| MCP server | 1.1 | Thin adapter once the core exists (§9). |
| Graham revised value | 1.1 | New calculation, not part of the port; never implemented anywhere. |
| Issue #4 (issue link in help), `!terms_of_use` | 1.1 | UX only; no architectural impact. |
| Club portfolio features | later, redesigned | Removed in ADR-0004; rebuild on the new core if needed. |
| Semiannual filers | later | ADR-0001's 4-quarter rule stands. |

## 4. Architecture

```
            ┌──────────────┐   ┌──────────────┐   ┌───────────────────┐
 front ends │ stockyard.bot│   │ stockyard.cli│   │ stockyard.mcp (1.1)│
 (adapters) │  "Warren"    │   │  `stockyard` │   │                    │
            └──────┬───────┘   └──────┬───────┘   └─────────┬──────────┘
                   │  results          │ results             │ results
            ┌──────▼───────────────────▼─────────────────────▼──────────┐
 renderers  │ stockyard.render: discord · text · json · charts            │
            └──────▲─────────────────────────────────────────────────────┘
                   │ typed results (frozen dataclasses)
            ┌──────┴─────────────────────────────────────────────────────┐
 core       │ stockyard.research: build_report(), one function per section │
            │ stockyard.data:     fetch (yfinance) · cache · fundamentals  │
            └─────────────────────────────────────────────────────────────┘
```

**Dependency rule:** arrows point down only. `research` and `data` import nothing from `render`,
`bot`, `cli`, `discord`, `matplotlib`, or `prettytable`. A test enforces this (§11).

### 4.1 Package layout

```
src/stockyard/
  __init__.py            # version only; no side effects on import (no log lines)
  __main__.py            # `python -m stockyard` → CLI
  config.py              # Settings resolved from env: data dir, cache on/off
  logging_config.py      # logs go to stderr, never stdout
  data/
    yfinance_source.py   # raw fetchers (today's yfinance_integration.py, minus orchestration)
    cache.py             # on-disk, same-day cache of raw frames (§7)
    fundamentals.py      # ADR-0001 builder: aligned_annual_fundamentals()
    snapshot.py          # StockData: everything one report needs, fetched once
  research/
    models.py            # frozen dataclasses for every result type
    sections.py          # one pure function per SSG section
    report.py            # build_report(ticker, as_of, sections=...) orchestration
  render/
    text.py              # terminal tables (prettytable)
    discord.py           # Discord markdown + 2000-char chunking
    json.py              # envelope + to_dict serialisation, schema version
    charts.py            # matplotlib PNGs into a caller-supplied directory
  bot/
    __init__.py          # Warren: discord.py client; entry point `warren`
  cli/
    __init__.py          # argparse; entry point `stockyard`
```

Console scripts (`pyproject.toml`): `stockyard = "stockyard.cli:main"`, `warren = "stockyard.bot:main"`.
Docker `CMD` becomes `-m stockyard.bot`.

## 5. Core

### 5.1 Data acquisition — `StockData`

`fetch_stock_data(ticker, *, cache) -> StockData` performs the six yfinance calls **once** and returns an
immutable bundle: income statement (annual + quarterly), balance sheet, cash flow, earnings, daily and
monthly prices. Every section reads from a `StockData`; no section fetches.

This is the seam for tests (build `StockData` from recorded fixtures, no network) and for the MCP server
(fetch once, answer several tool calls).

### 5.2 Aligned Annual Fundamentals (ADR-0001, issue #5)

`aligned_annual_fundamentals(data: StockData) -> AlignedFundamentals` implements ADR-0001 as specified in
`docs/requests/work-item-1.md`: Complete Fiscal Years keyed by income-statement period-end, a separate
in-progress Current Year, and a `sufficient_history` flag. Every year-over-year comparison (Past Sales,
Past EPS, Record of Stock, Revenue Growth, annual EPS in Risk & Reward) reads this structure.

**Extension beyond ADR-0001 (flagged for review):** Record of Stock currently takes each year's high/low
price from the *calendar* year (`monthly_prices.loc["2025"]`). For a non-December filer that window is
not the fiscal year. v1 takes price windows from `(previous period-end, period-end]` so prices, EPS and
revenue all describe the same fiscal year.

### 5.3 Determinism — `as_of`

Every section takes an `as_of: date`. Look-back windows ("last 5 years"), "present price" and the
five-year forecast horizon derive from `as_of`, never `datetime.now()`. Front ends pass today's date.
Tests pin it, so fixture-based expectations never drift.

### 5.4 Sections and results

One pure function per SSG section, `section(data, fundamentals, as_of) -> Result`. Result types are
frozen dataclasses in `research/models.py`, each with `to_dict()`. Field-level names are settled by the
tests that drive them; the shapes are:

| Section (`id`) | Result carries |
|---|---|
| `fundamentals` | complete years (`fiscal_year`, `period_end`, `revenue`, `reported_eps`), current year (`quarters_reported`, to-date figures), `sufficient_history` |
| `past_sales` | revenue per FY, recent-pair average, oldest-pair average, % increase, CAGR |
| `past_eps` | reported EPS per FY, pair averages, % increase, CAGR |
| `record_of_stock` | present price, TTM EPS, per-FY high/low/EPS/PE-high/PE-low/dividend/payout/high-yield, averages, average PE, current PE, % vs. high N years ago |
| `trend` | quarterly revenue and EPS series (data for charts; no images) |
| `cash_position` | per metric: latest, prior, difference, % difference — assets and liabilities |
| `revenue_growth` | revenue per FY with change and % change, average growth, dividend figure, current PE, growth-rate-with-dividends |
| `earnings_growth` | net income per FY with change and % change |
| `risk_reward` | 5-year high-price forecast **or** the reason none is quoted; four low-price estimates (linear regression, 5-yr average low, severe low, dividend support); buy/maybe/sell zones and up/down ratio per estimate; price target and implied appreciation; forecast series for charts |

`build_report(data, as_of, sections=ALL) -> Report` runs the requested sections and collects warnings.

### 5.5 Partial history and failures (issue #2)

* A section that cannot be computed from the available history returns `None` for the affected fields
  and adds a structured warning (`code`, `message`, `section`). It does not raise.
* `insufficient_history` is a report-level warning when `sufficient_history` is false.
* Unknown ticker / no data at all → `DataUnavailable` exception (front ends map it: CLI exit 3, Discord
  "No data available for X").
* Network or upstream failure → `UpstreamError` (CLI exit 4).
* Ratios are stored as fractions (`0.123`, not `12.3`); rendering applies `%`.

## 6. Rendering

* **Discord** keeps today's section order and headings, adds `FY####` labels and warning lines, chunks
  at 2000 characters, and attaches chart PNGs.
* **Text** is the Discord content without Discord markdown.
* **JSON** (§8.2) serialises `to_dict()` output. Never contains images.
* **Charts** are drawn from result series into a directory the caller supplies (a per-request temporary
  directory in the bot; `--charts DIR` in the CLI). This replaces today's fixed filenames
  (`eps_pred_fig.jpg`, …), which concurrent `!sr` requests overwrite.

## 7. Caching

An agent typically runs several CLI processes in a row (`stockyard eps MSFT`, then `stockyard
risk-reward MSFT`); without a shared cache each process repeats the six yfinance calls.

* Raw yfinance frames are cached on disk under `$STOCKYARD_DATA_DIR/cache/<TICKER>/<dataset>.json`,
  valid for the **calendar day** they were fetched (data is end-of-day).
* Format is pandas `to_json(orient="split")` — **not pickle**: loading a pickle from a writable data
  directory is arbitrary code execution.
* `--no-cache` bypasses reads and writes. The bot uses the same cache.

## 8. Front ends

### 8.1 CLI

```
stockyard report TICKER        all sections
stockyard <section> TICKER     one section: fundamentals, past-sales, past-eps, record, trend,
                               cash, revenue-growth, earnings-growth, risk-reward
options:  --json  --charts DIR  --no-cache  -v/--verbose
```

| Exit code | Meaning |
|---|---|
| 0 | success (warnings may be present) |
| 1 | unexpected internal error |
| 2 | usage error (argparse) |
| 3 | data unavailable for ticker |
| 4 | upstream/network failure |

**stdout carries only the result.** Logs and progress go to stderr, so `stockyard report MSFT --json |
jq` always parses. (Today the package logs a JSON line on import; that goes away.)

### 8.2 JSON contract

```json
{
  "schema": "stockyard.report/1",
  "ticker": "MSFT",
  "as_of": "2026-11-11",
  "source": "yfinance",
  "currency": "USD",
  "warnings": [{"code": "insufficient_history", "section": null, "message": "..."}],
  "sections": { "past_eps": { ... }, "risk_reward": { ... } }
}
```

* Single-section commands emit the same envelope with one key in `sections`.
* Errors with `--json` emit `{"schema": "stockyard.error/1", "code": ..., "message": ...}` on stdout
  with the matching non-zero exit code.
* Dates are ISO-8601; fiscal years appear as both `"fiscal_year": "FY2025"` and `"period_end"`.
* Missing values are `null`, never `NaN` (invalid JSON) or `0`.
* **Compatibility:** adding fields is non-breaking; renaming, removing or changing the meaning of a field
  bumps the schema to `/2`.

### 8.3 Discord bot (Warren)

* Commands: `!stock_report`/`!sr TICKER`, `!help`.
* The blocking yfinance + pandas work runs in `asyncio.to_thread` so the event loop (and the gateway
  heartbeat) is never blocked. Today it runs on the loop.
* The token is resolved when the bot starts, not at import time, so importing the package never needs a
  Discord token.

## 9. Path to v1.1 (MCP server)

Nothing in the v1 core changes for MCP. `stockyard.mcp` will expose one read-only tool per section plus
`report`, returning the same `to_dict()` payloads as the JSON contract, using stdio transport first.

## 11. Testing strategy

Strict TDD per `CLAUDE.md`: no production code without a failing test first.

* **Calculations:** expected values derived from the definition (hand-computed from fixture inputs),
  extending the existing `test_stock_analysis_calculations.py` approach. The 0.1 output is not an oracle
  (D5).
* **Fixtures:** recorded yfinance responses (`IBM.yfinance.json`, `scripts/refresh_test_fixtures.py`).
  Add a **non-December filer** (e.g. MSFT, FY ends 30 June) and a **short-history** company for #2.
  Synthetic frames for edge cases (3-of-4 quarters, negative EPS trend, zero division).
* **Architecture test:** importing `stockyard.research` and `stockyard.data` must not import `discord`,
  `matplotlib`, or `prettytable`.
* **CLI:** `main(argv)` tested in-process; asserts stdout is valid JSON, exit codes, stderr-only logging.
* **JSON contract:** a schema-shape test pins the `/1` envelope so accidental breaking changes fail CI.
* **Bot:** handler tests with fake message/channel objects; no Discord connection.
* No network in the test suite.

## 13. Delivery

* Work on `feature/v1` in the worktree `.worktrees/v1`; small red-green-refactor commits, unsigned.
* Before merge: owner reviews and re-signs —
  `git rebase --exec "git commit --amend --no-edit -S" main` — then merges to `main` on GitHub.
* Release: `bump-my-version major` → `1.0.0`, CHANGELOG entry, tag.
* Order of work: `docs/design/v1-plan.md`.

## 14. Risks

| Risk | Mitigation |
|---|---|
| D5: a calculation changes unintentionally and nothing flags it | definition-derived tests per formula; owner reviews numeric output on 2–3 known tickers before release |
| yfinance schema drift breaks fetchers | fixture refresh script + field maps isolated in `data/` |
| Agents depend on JSON fields that later change | versioned schema, compatibility rule §8.2 |
| Big-bang rewrite of `stock_analysis.py` | sections migrate one at a time behind the existing tests (plan, phase 3) |

## 16. Suspected defects found during design review — for triage

Not fixed silently; each needs an owner decision (fix in v1 with a failing test, or file an issue).

1. **Revenue Growth "div yield"** is `dividendPayout / shares_outstanding`: a dividend *per share* in
   dollars, not a yield (which would divide by price). The sign is already correct: the fetcher takes the
   absolute value of yfinance's negative `Cash Dividends Paid`.
2. **"Growth Rate w/ Dividends"** computes `((avg_growth × 10) + dividend) / PE`, mixing a fraction × 10
   with a dollar-per-share amount. The SSG-style intent is probably `(growth % + yield %) / PE`.
3. **Record of Stock price windows** use calendar years (see §5.2).
4. **Concurrent `!sr` requests** overwrite each other's chart files (§6).
5. **The bot blocks its event loop** during report generation (§8.3).
6. **`docker-compose.yml` healthcheck** calls `stockyard.health_check()`, which has never existed.
7. **`.github/workflows/build.yml`** lints `setup.py`, which does not exist, and does not run tox.
